# Palma web execution

Merge phd-experiments PR 5 before enabling this feature. Set PHD_ACTIONS_TOKEN server-side to a fine-grained token limited to the private phd-experiments repository with Actions read/write and metadata read. Mount datasets and results read-only and set PHD_DATASETS_DIR and PHD_RESULTS_DIR. Never expose the token to the client. Existing authentication middleware remains required.

Open an existing experiment, select one or more ratios and optionally a full commit, and click Run experiment. The workflow supports sample_0001 variants quick_4rows, slab_16rows and slab_32rows when their local manifests are available. Larger slabs allow one ratio initially. Merge tomo-mct-pipeline PR 26 and phd-experiments PR 7 first. Existing requests default to quick_4rows. Experiment ID is assigned automatically. The local manifest is checked and registered if necessary. A UUID correlates the dispatch with its GitHub workflow run; exact run ID and attempt identify the completed local ZIP. The scientific manifest and dataset checksum must match the request before importing. No archive is uploaded to GitHub.

Status and result synchronization run on opening the Runs section and every 15 seconds while it remains visible, or on manual refresh. This is not a background worker. Only one active web request is allowed globally. GitHub may still accept manual runs; do not dispatch competing jobs manually. If the dispatch outcome is unknown or a successful run cannot be imported, inspect GitHub and local results before manually releasing the request. Manual ZIP import remains available. Back up PostgreSQL before deployment.

Multiple ratios require phd-experiments PR 6. All selected ratios run in one pipeline invocation with a shared uncompressed reference. Existing single-ratio history remains valid. Local Palma imports allow 128 MiB archives and 256 MiB expanded; manual uploads retain 32 MiB archives and 64 MiB expanded. Both retain 12 MiB per file and 512 files. The 60-minute workflow limit remains. Test small sweeps before selecting all six. Large local imports may take up to 120 seconds in the database transaction.

## Artifact storage

Set PHD_ARTIFACTS_DIR to a persistent private writable mount owned by the web service. Do not mount it into the runner or expose it through a static web server. New imports store validated files by SHA-256 digest, with paths, hashes and sizes in PostgreSQL. Existing database-backed files remain readable. Original runner ZIPs are untouched. The archive validation and upload limits remain in place. Disk writes precede database commits; interrupted imports can leave unreferenced objects, which are safe to retain and reused on retry. Do not garbage collect objects while imports or migration are active.

After backing up PostgreSQL and the artifact directory, optionally migrate existing files using `docker compose ... exec phd-web node scripts/migrate-run-artifacts.cjs`. The command is resumable and verifies the written file before removing its database payload. Back up both PostgreSQL and the artifact directory together going forward. Do not roll back to an old app version after migrating binary payloads without restoring the corresponding database backup.
